# 원문 편집·자동 저장

기본 화면은 읽기다. 상단 **읽기 / 편집**으로 원문 Markdown 편집기를 연다. 별도 실시간 미리보기·Obsidian Live Preview는 없다. 입력이 1초 멈추면 저장하며 Ctrl+S·Cmd+S와 저장 버튼은 즉시 저장한다. 수정 중 / 저장 중 / 저장됨 / 저장 실패를 표시한다.

문서별 초안과 저장 큐를 유지한다. 저장 중 입력한 최신 본문은 이전 요청의 응답으로 덮지 않고 새 revision으로 이어서 저장한다. 읽기 전환·다른 문서 이동·탭 닫기에도 시작한 저장은 진행한다. 앱 종료 시 원격 저장 완료를 기다리는 짧은 종료 콜백에 의존하지 않는다.

클라이언트 제품 CLI가 고른 OS 사용자 data/client-drafts 아래에 원자적 로컬 초안을 기록한다. 대상 머신·실행 파일·Vault 등록명·상대 경로로 초안을 구분한다. 재시작 뒤 해당 문서를 열면 미저장 초안을 복구하고 사용자가 확인 후 재시도한다. 실패 시 초안을 유지한다. 원본 다시 읽기는 기존 초안을 recovered 기록에 보존한 뒤 원본을 가져온다. 초안·복구 기록은 자동 만료하지 않는다. 같은 클라이언트의 별도 reader가 같은 문서를 동시에 편집해 초안 파일이 달라지면 CAS 검사가 실패하며 다른 초안을 조용히 덮지 않는다. 로컬 파일 기록이 끝나기 전의 강제 종료까지 무손실을 보장하지는 않는다.

읽기 화면의 목록 `- [ ]`, `- [x]`, `- [X]`는 체크 표시를 클릭해 즉시 저장한다. 일반·중첩 목록의 상태 문자 하나만 변경하며 완료는 소문자 x, 해제는 공백이다. 프론트매터·펜스/들여쓰기 코드·주석·사용자 정의 `[?]`, `[-]`는 바꾸지 않는다. 렌더링마다 생성한 링크 식별자를 원문 위치에 매핑하며 전용 링크는 실제 문서에 쓰지 않는다. 위키링크 이동은 유지한다.

## 저장 계약

본문 편집과 체크박스는 같은 Rust storage::write 경로를 사용한다. Vault별 OS 잠금 아래 현재 revision을 확인하고 data/recovery/<vault-id>/write-<operation>에 original.bin·new.bin·prepared.json을 먼저 기록·sync한다. Vault의 같은 디렉터리에 임시 파일을 쓰고 sync한 뒤 경계·revision을 다시 검사하여 원자적으로 교체한다. 완료는 completed.json에 남긴다. 실패 시 원본 직접 잘라 쓰기로 전환하지 않는다. 공개 이후 sync/완료 기록 실패라면 오류가 나더라도 이미 저장됐을 수 있으므로 원본을 다시 읽고 복구 기록과 비교한다.

UTF-8 BOM과 기존 LF·CRLF·CR 단일 줄바꿈 형식을 보존한다. 편집기 줄바꿈은 저장 시 원래 형식으로 정규화한다. 줄바꿈 없는 문서의 새 줄바꿈은 LF를 쓴다. 혼합 줄바꿈·미지원 인코딩·NUL 문서는 읽기 전용이다. 1 MiB 문서 제한과 기존 경로 이탈·symlink/reparse 차단을 유지하고 하드링크 저장을 거부한다. 기존 파일 permissions를 복사하지만 소유권·확장 속성·Windows 개별 ACL의 완전한 보존은 보장하지 않는다.

Obsidian/Headless Sync 등 외부 작성자는 herdrmd 잠금을 따르지 않는다. 최종 revision 검사와 교체 사이의 외부 쓰기 경쟁 및 같은 사용자 권한의 악의적 디렉터리 교체를 완전히 격리하지 않는다. 관찰한 원본과 작성본을 복구 기록으로 보존한다. NAS 저장 이후 기기 간 동기화는 기존 Headless Sync가 담당한다.

## 설치

NAS의 제품 실행 파일과 별도로 각 클라이언트 mod 폴더에 최신 로컬 herdrmd(macOS) 또는 herdrmd.exe(Windows)가 필요하다. options.localBinary로 다른 로컬 절대 경로를 지정할 수 있다. options.binary는 Vault가 있는 호스트의 제품 CLI이며 machine이 있으면 기존 hc 연결로 호출한다. 원격 본문은 로컬 요청 파일 → 제품 relay → hc exec --stdin → 원격 write 경로로 전달한다. 본문은 명령 인수에 넣지 않는다. Herdr 본체·Sync 설정은 변경하지 않는다.

append·일반 복구 관리 CLI·외부 변경 실시간 감지·자동 충돌 병합은 아직 제공하지 않는다.

검증용 mod를 설치할 때는 `mod.json`의 `place: "none"`을 main.js보다 먼저 둔다. 설정이 없는 새 mod를 Herdr가 감지하면 기존 레이아웃에 고정 패널로 자동 배치할 수 있다. 검증은 명시적 탭 하나에서 수행하고 탭·레이아웃·합성 상태 정리를 확인한다.
