# 문서 이동과 링크 갱신 검토

상태: 2026-11-01 조사·후속 설계. 현재 herdrmd에는 move/rename·링크 일괄 재작성·외부 이동 자동 복구가 없다. 이번 변경에서 실제 노트의 경로/링크는 수정하지 않는다.

## 목표와 범위

`A/노트.md`를 `B/노트.md`로 옮길 때 그 문서를 가리키던 링크만 갱신한다. `[[A/노트#절|표시]]`는 `[[B/노트#절|표시]]`로 바꾸고 fragment·표시 이름·BOM·줄바꿈·다른 본문은 유지한다. `[[노트]]`가 이동 후에도 같은 문서로 유일하게 해석되면 그대로 둘 수 있다. 단순 문자열 일괄 치환으로 코드 예제나 다른 동명 문서를 바꾸지 않는다. 폴더 이동은 파일 이동·링크 수정 계획을 묶는 후속 단계로 둔다.

## 실행 경로별 판단

| 경로 | 구현 방향 | 난점 |
| --- | --- | --- |
| Herdr 안에서 파일 이동/이름 변경 | 이동 전후 경로를 알고 참조 노트 변경 계획을 만든 뒤 함께 처리 | 여러 파일의 revision·동시 Sync·중간 실패 |
| Obsidian 안에서 이동/이름 변경 | Obsidian의 내부 링크 자동 갱신 기능 사용, Herdr의 목록/문서 캐시 갱신 | NAS에 반영되는 Sync 지연 |
| 외부 탐색기·다른 도구에서 이동 | 이전 관측과 현재 파일의 후보를 비교하고 불확실하면 복구 후보 제시 | Sync가 삭제+생성으로 보일 수 있고 복사본/동일 내용/동시 편집으로 추정이 모호함 |

[공식 Obsidian 설정](https://obsidian.md/help/settings)은 내부 링크 자동 갱신을 제공한다. [공식 CLI](https://obsidian.md/help/cli)의 move/rename도 설정이 켜져 있으면 링크를 갱신한다. 이 CLI는 실행 중인 데스크톱 앱이 필요하다. [Headless](https://obsidian.md/help/headless)는 독립 Sync/Publish 클라이언트이며 같은 데스크톱 파일 관리 API를 제공한다고 가정하지 않는다. 현재 NAS Headless Sync를 공식 CLI 대용으로 자동 교체하지 않는다.

## 권장 구현 순서

1. 기존 문서 저장·expected revision 비교·복구 기록과 미완료 작업 관리부터 완성한다.
2. Herdr 내부의 단일 파일 move/rename과 해당 문서를 가리키는 위키링크 갱신을 먼저 구현한다. 대상 파일과 참조 노트들의 변경 전 revision, 경로 및 원본/작성본을 기록한다. 접근 불가나 검색 한도로 참조 집합이 불완전하면 조용히 완전한 일괄 갱신으로 보고하지 않는다.
3. 파서가 실제 링크로 해석한 원문 byte 범위만 바꾼다. 코드·이스케이프·fragment·표시 이름을 보호한다. 일반 Markdown 상대 링크·임베드·속성 내 링크 등 미지원 범위는 계획에 명시하고 지원을 확장한다.
4. Vault 잠금 아래 revision을 재검사하고 각 파일은 안전 교체한다. 여러 노트와 이동을 파일시스템의 단일 원자적 작업으로 보장할 수 없으므로 진행 저널과 실패/재시도/복구 상태를 둔다. 외부 Sync는 잠금을 따르지 않는 점을 처리한다.
5. 완료 후 UI의 옛 탭/트리/향후 링크 인덱스를 무효화한다. 예전 경로→새 경로 이동 기록을 활용해 오래 열린 노트의 링크를 누를 때 옛 위치에 빈 노트를 다시 만드는 상황을 막는다. 이동 기록의 문서 동일성·경로 재사용·연쇄 이동도 검증한다.
6. 폴더 이동을 추가하고, 외부 이동은 관찰/후보 제안부터 시작한다. 해시나 파일시스템 ID만으로 문서 동일성을 확정하지 않는다. Sync를 거치는 자동 이동 복구는 별도 범위다.

기본 구현은 충분히 가능하다. 복잡도가 큰 부분은 링크 문자열 변경 자체보다 여러 문서의 안전한 수정과 외부 이동/Sync 충돌의 식별이다. 합성 Vault로 동명 노트·표시 이름·제목/블록·이동 중 외부 수정·중간 종료·이전 링크의 빈 파일 재생성을 검증한 뒤 실제 Vault에 적용한다.
